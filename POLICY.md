# Политика качества и приёмки

## Запреты (п.14 общих требований)

1. **Запрещено** удалять или комментировать тесты ради прохождения проверки.
2. **Запрещено** отключать анализаторы (phpcs, phpstan) или ослаблять их правила без явного обоснования в PR.
3. **Запрещено** снижать порог покрытия кода (`COVERAGE_MIN` в Makefile, сейчас **40%**) без обоснования и обсуждения.
4. **Запрещено** добавлять `@phpstan-ignore`, `// phpcs:ignore` и аналогичные исключения без комментария с причиной в том же коммите/PR.
5. **Запрещено** ослаблять CI или локальный `make verify` только для «зелёного» статуса.

## Обязательный локальный контроль

Перед любым merge/push студент обязан выполнить:

```bash
make verify
```

Команда запускает: lint → статический анализ → SAST → тесты с проверкой покрытия ≥ 40%.

## Процесс изменений

- Каждая новая функция — отдельная ветка и pull request.
- Изменения критических файлов приёмки (Makefile, phpunit.xml, phpstan.neon, phpcs.xml, scripts/check_coverage.php) должны быть видны в PR и отдельно ревьюироваться.
- Финальная приёмка включает живую демонстрацию и контрольное изменение (или осознанный отказ).

## Мутационное / граничное тестирование

Unit-тесты `Validator` и интеграционные тесты `RaceService` покрывают:

- обязательные поля;
- граничные длины строк и числовые диапазоны;
- некорректные ID, даты, статусы;
- сценарии с чистой БД и БД с уже существующими данными.
